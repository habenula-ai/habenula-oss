# Getting Started (Development)

From a fresh clone to a running engine + CLI.

## Prerequisites

- Node.js (version pinned in `.mise.toml`) — script runtime, and required for `@cloudflare/vitest-pool-workers`
- npm (ships with Node) — package manager; install deps with `npm ci`
- Wrangler CLI (invoked via `npx wrangler`; no global install needed)

Local development runs entirely against Miniflare — **no Cloudflare account
needed**. An account (Workers and Durable Objects enabled) and `wrangler
login` are required only to **deploy**.

## Install

Do this once after cloning. Run from the repository root:

```bash
mise install       # pinned node / just
npm ci             # pinned deps from package-lock.json
just setup         # installs the git pre-commit hook + scaffolds .dev.vars
```

## Environment setup

Engine config lives in the git-ignored `packages/engine/.dev.vars` for local dev.
`wrangler.toml` holds non-secret config only, so `.dev.vars` is the sole local
source for every key and credential.

`just setup` (and the `just dev` preflight) creates the file for you when it is
missing. In a linked git worktree it copies your main checkout's `.dev.vars`.
Otherwise it copies `.dev.vars.example` and generates real values for the two
local secrets. An existing `.dev.vars` is never touched. To create it by hand
instead, run this once from the repository root:

```bash
cp packages/engine/.dev.vars.example packages/engine/.dev.vars
```

The required values — the engine and CLI **fail closed** without them:

- **`CREDENTIAL_ENCRYPTION_KEY`** (required, generated by the scaffold) — with
  no key, a malformed key, or one of the publicly known dev placeholder keys,
  the engine returns 503 on every route except `/api/health`. To set one by
  hand: `openssl rand -hex 32`.
- **`ANTHROPIC_API_KEY`** (required for the conversation, never auto-filled) —
  a real Claude API key; this is the one value you must set yourself. To use a
  different provider instead, set `LLM_PROVIDER` (see `.dev.vars.example`).
- **`INTERNAL_MCP_TOKEN`** (required for the conversation, generated by the
  scaffold) — the caller token for the trusted `/internal/mcp` drive surface.
  If it is unset, every conversation turn returns 401. The CLI must present
  the same value via `HABENULA_INTERNAL_MCP_TOKEN`. `just dev` exports that
  for you. The two-terminal flow needs it exported by hand.

After any `.dev.vars` change, restart the engine — `wrangler dev` does **not**
hot-reload it.

## Local Development

Cloudflare's Wrangler supports local emulation of Workers, KV, R2, and Durable Objects (including built-in SQLite) via Miniflare.

The one-command start runs both processes. This is the loop you will use every
day. Run from the repository root:

```bash
just dev              # start the engine, wait for /api/health, run the CLI
```

It runs a preflight first:

- Scaffolds `.dev.vars` when it is missing (see Environment setup above).
- Warns — without blocking — when a required value is empty or still a
  placeholder.
- Exports `HABENULA_INTERNAL_MCP_TOKEN` from the engine's `INTERNAL_MCP_TOKEN`,
  so the CLI authenticates without a manual export.

After the preflight, it starts the engine in the background and polls
`GET /api/health` until the engine serves. The poll is bounded: a failed
engine boot prints the captured engine output and exits non-zero instead of
hanging. It then runs the interactive CLI in the foreground. The engine is
torn down when the CLI exits.

The two-terminal flow remains for debugging. Run each command from the
repository root, in its own terminal:

```bash
just engine-dev       # terminal 1: the engine (wrangler dev)
just cli-dev          # terminal 2: run the CLI from source
```

Start either first — the ordering is safe. The CLI treats a not-yet-running engine as a first-class offline state: it prints one guidance line, probes `GET /api/health` on a backoff, and recovers on its own the moment the engine comes up. No CLI restart needed.

## First Run

With `.dev.vars` set, `just dev` boots the engine, waits for `/api/health`, and
drops you into the CLI. You should see the **HABENULA launch banner**. A plain
line is a conversation turn to the agent; a line starting with `:` is a
meta-command (`:connect`, `:status`, `:kill`, `:quit`, `:help`).

Send a line (e.g. `say hello`) and confirm the agent responds. If it errors with
`internal interface rejected the caller token`, your `HABENULA_INTERNAL_MCP_TOKEN`
does not match the engine's `INTERNAL_MCP_TOKEN` — under `just dev` that only
happens when your shell exports its own stale value, which wins over the value
`just dev` exports. If every route 503s, the engine is still on the placeholder
`CREDENTIAL_ENCRYPTION_KEY`.

Confirm your toolchain by running the tests inside the Workers runtime. Do this
once, from the repository root:

```bash
just engine-test
```
